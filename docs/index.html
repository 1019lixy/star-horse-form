快速上手

本文档介绍如何安装、配置并在 Vue 3 项目中使用 StarHorseForm。

环境要求

  • Node.js >= 20.13.0
  • Vue 3.5+
  • Element Plus 2.14+
  • 依赖核心库 star-horse-lowcode（本组件包以 ../shplugin 本地引用，发布时随包打包）

安装

npm install star-horse-form
# 或
pnpm add star-horse-form

若以源码方式使用（monorepo），package.json 中已配置 "star-horse-lowcode": "../shplugin"，确保同级目录存在 shplugin 项目。

全局配置

在 main.ts / main.js 中引入样式并安装插件：

// 样式（顺序：核心库 → 本组件包 → element-plus）
import "star-horse-lowcode/assets/index.css";
import "star-horse-form/assets/index.css";
import "element-plus/dist/index.css";

import { createApp } from "vue";
import App from "./App.vue";
import StarHorseForm from "star-horse-form";

const app = createApp(App);

app.use(StarHorseForm, {
  // 可选配置项
  router,                 // Vue Router 实例
  axiosInstance,          // 外部传入 axios 实例（否则使用默认）
  elementPlusOptions,     // Element Plus 配置选项
  lang: "zh-CN",          // 国际化语音
  initElementPlus: true,  // 是否初始化 element-plus（默认 true）
});

app.mount("#app");

install 方法签名

install(
  app: App,
  options?: {
    router?: any;
    axiosInstance?: any;        // 外部传入 axios 实例，否则使用默认
    elementPlusOptions?: any;   // Element Plus 配置选项
    lang?: LangType;            // 国际化语音
    initElementPlus?: boolean;  // 是否初始化 element-plus
  }
)

install 内部执行顺序：

  1. 注册全局 draggable 组件（vuedraggable-es）
  2. 初始化本组件包的 Pinia store
  3. 安装 star-horse-lowcode 核心库（透传 options）
  4. 异步注册 system/*.vue、system/items/utils/*.vue、formcomp/items/*.vue、formcomp/container/*.vue 下所有组件
  5. 注册 formContext 上下文

后端端点配置（无状态注入）

本组件包遵循无状态 lib 库原则，不绑定任何特定业务的接口地址。对接自有后端时，请在 main.ts 中、渲染任何表单/规则组件之前调用两个全局配置函数：

import {
  configureRuleEngine,
  configureAppEndpoints,
} from "star-horse-form";

// 1) 规则引擎 9 组 CRUD/执行接口的服务名与路径
configureRuleEngine({
  serviceName: "my-service",       // 默认 userdb-manage
  ruleEnginePath: "api/ruleEngine", // 其余 8 组路径同理可覆盖，未传则用默认
});

// 2) 全局通用端点（WebSocket / 代理 / 字典 / 网关等），按需覆盖
configureAppEndpoints({
  wsEndpoint: "/my-ws/form",                    // 协同编辑 WebSocket，默认 /api/ws/form
  apiLinkageProxyUrl: "/gw/redirect/apiLinkage", // http-call 代理，默认 /system-config/redirect/apiLinkage
  executeProxyUrl: "/gw/redirect/execute",       // 接口执行代理，默认 /system-config/redirect/execute
  gatewayPrefix: "/my-service",                  // 网关前缀，默认 /userdb-manage
  gatewayServiceName: "my-service",              // apiInstance 服务名，默认 userdb-manage
});

未配置时使用内置默认值保证开箱可用；重复调用按字段合并覆盖。字段含义详见 前端 API 层 - 端点配置。

核心数据流

表单设计数据流

用户拖拽配置
      │
      ▼
StarHorseFormDesign ──→ compList（组件树配置）
      │                      │
      │                      ├── 保存到后端（api.saveData）
      │                      └── 预览渲染

                              │
                              └── 渲染表单项 + 联动 + 数据源

规则引擎数据流

表单运行时
      │
      ├─ ON_LOAD  ──→ triggerOnLoad()  ──→ executeByForm(formId, "ON_LOAD", formData)
      ├─ ON_CHANGE ──→ triggerOnChange() (300ms 防抖) ──→ executeByForm(formId, "ON_CHANGE", formData)
      ├─ ON_SUBMIT ──→ triggerOnSubmit() ──→ executeByForm(formId, "ON_SUBMIT", formData)
      ├─ ON_VALIDATE ──→ triggerOnValidate()
      └─ ON_BUTTON_CLICK ──→ triggerButtonClick(buttonKey)
                                    │
                                    ▼
                        后端规则引擎执行
                                    │
                                    ▼
                        mergedContext（含 __visible_xxx 等前缀字段）
                                    │
                                    ▼
                        parseFieldActions() ──→ FieldAction[]
                                    │
                                    ▼
                        applyActionsToFormFields() ──→ 应用到 compList
                              ├─ field.formVisible    （显隐）
                              ├─ field.required       （必填）
                              ├─ field.preps.disabled （禁用）
                              ├─ field.preps.readonly （只读）
                              ├─ field.preps.options  （选项）
                              └─ formData[field]      （赋值）

三套联动机制的关系

机制 层级 执行方式 触发时机 优先级
dataRelation 字段级 同步 字段变更立即执行 低（先执行）
apiLinkage 字段级 异步 字段变更触发接口 中
规则引擎 表单级 异步（300ms 防抖） 表单级 watch formData 高（覆盖前者）

执行时序：字段变更 → dataRelation 同步 → apiLinkage 异步 → 300ms 后规则引擎异步 → 覆盖前者。

表单设计器（StarHorseFormDesign）

表单设计器是 StarHorseForm 的核心组件，提供可视化拖拽式表单设计能力。设计器内置 50+ 表单项、20+ 布局容器，支持配置模板复用、快捷键、预览、导出 HTML、自定义组件接入、规则引擎配置入口等。

源码位置：src/components/system/StarHorseFormDesign.vue

基本用法

<script setup lang="ts">
import { StarHorseFormDesign, type FormConfig } from "star-horse-form";

const optional: FormConfig = {
  model: "full",
  primaryKey: "id",
  api: { basePrefix: "/userdb-manage/userdb/formDesign" },
};
</script>

<template>
  <StarHorseFormDesign :optional="optional" />
</template>

通过 FormConfig.itemList 注入：

const optional: FormConfig = {
  model: "default",

数据源与联动配置

表单项的属性面板支持配置数据源与联动策略，相关类型定义于 src/components/types/DataSourceTypes.ts：

  • 静态数据源（dataSource: "data"）：直接配置选项数组。
  • 内部接口数据源（dataSource: "url"）：通过服务名 + 接口名 + 方法名调用内部接口，支持网关转发。
  • 字典数据源（dataSource: "dict"）：通过字典编码加载，依赖 FormConfig.loadDicts。
  • 第三方接口数据源（dataSource: "thirdParty"）：完整 HTTP 请求配置（方法/协议/头/参数/认证/响应映射）。

联动策略：

  • dataRelation：字段级可见性联动（同步）。
  • apiLinkage：字段级接口联动（异步，含请求/响应/认证/字段映射完整配置）。
  • 规则引擎：表单级规则（最强，详见 规则引擎设计器）。

数据源与联动的完整类型定义详见 DataSourceTypes.ts。

节点类型定义

定义于 src/components/rule/nodeTypes.ts。遵循无状态 lib 库原则，节点采用注册表模式：

  • 内置 2 大类 8 种节点仅作为默认注册集，保证开箱可用，并非封闭穷举；
  • 宿主应用可在运行时增删节点与分类（configureRuleNodes / registerRuleNode 等），无需修改本库代码；
  • 注册表为 Vue 响应式状态，节点面板/画布/属性区自动跟随更新。

NodeTypeDef（节点类型定义）

interface NodeTypeDef {
  type: string;          // 节点类型标识（写入 flowContent.nodes[].type）
  label: string;         // 标签（支持 i18n key）
  icon: string;          // 图标
  category: string;      // 逻辑类别标记（flow/logic/...，供执行器识别）
  nodeClass: NodeClass;  // 节点大类：flow / condition / action
  desc: string;          // 描述（支持 i18n key）
  component?: Component; // 画布渲染组件；缺省回退 GenericNode 通用渲染
  editor?: Component;    // 统一协议属性编辑器：props { nodeData, itemIndex, variables }，emits save(patch)/close
  editorHint?: string;   // 属性面板弹窗编辑入口提示文案（i18n key）
  panelSection?: Component; // 属性面板片段组件：props { nodeData, variables }，emits update(patch)/configure(itemIndex?)
  uiEvents?: { editItemEvent?, deleteItemEvent?, listKey? }; // 子组件事件名映射
  getSummary?: (data) => string; // 节点配置摘要（画布卡片展示），由节点自行计算
  defaultData: () => Record<string, any>;  // 新建节点的默认数据（工厂函数）
  paramSchema: ParamField[];               // 属性面板参数 schema（generic 兜底渲染）
  estimateSize?: (data) => { width, height }; // 画布尺寸估算
  getEdgeLabel?: (ctx: { data, outIndex }) => { label, labelStyle? } | string; // 出边标签生成
  collectTestFields?: (data, fields, seen) => void; // 测试面板参数提取
  collectItems?: (data) => { listKey, items }; // 保存时按 listKey 拆解批量入库
}

统一数据结构体系

节点按 NodeClass 分为三大类，动作节点统一继承 actionType 派生标识：

基础节点：
  start (flow)       流程起点，可配置触发事件（ON_LOAD/ON_CHANGE/ON_SUBMIT/ON_VALIDATE/ON_BUTTON_CLICK）
  end (flow)         流程终点，可配置结束类型（success/fail/skip）
  condition (condition)  条件判断，AND/OR 逻辑 + 二分出边
  exclusive-gateway (condition)  多路分支路由，N 条出边 + 默认分支

动作节点（nodeClass: "action"，统一 actionType 派生）：
  action             actionType: FORM_CONTROL    表单控制（显示/隐藏/赋值/必填/设选项/提示）
  http-call          actionType: HTTP_CALL       HTTP 接口调用
  script             actionType: SCRIPT          脚本执行
  variable-assign    actionType: VARIABLE_ASSIGN 变量赋值

数据迁移：migrateFlowNodes(nodes) 在加载已保存规则时自动补齐旧数据缺失的 triggerEvent / actionType 字段，保证向后兼容。

可插拔架构要点

  • 节点业务全内聚：每个节点的定义、画布渲染、编辑器、面板片段、配置摘要、出边标签、尺寸估算、字段收集全部聚合在 nodes/{type}/index.ts 各自模块内；设计器（RuleDesigner / PropertyPanel / NodeEditorHost / GenericNode / RuleTestDialog）不感知任何具体节点类型，零 switch/case 类型分发。
  • getSummary 钩子：各节点自带 getSummary(data) 计算配置摘要（如条件数、动作数、HTTP 方法等），GenericNode 通用渲染调用 nodeDef.getSummary(data) 展示，不再硬编码类型分支。
  • collectTestFields 钩子：测试对话框 loadSampleData 通过注册表钩子收集测试参数，不再硬编码 node.type === "condition" 等类型判断。
  • 字段引用同步：ruleFieldSync.ts 使用 resolveNodeType + paramSchema fieldSelect 标记替换字段引用，不再硬编码类型分支。
  • panelSection 机制：基础类型节点（condition/action/variable-assign/exclusive-gateway）各自提供 panelSection 组件，PropertyPanel 动态渲染 <component :is="nodeDef.panelSection">，不再硬编码类型分支。新增节点可自带定制面板片段。
  • 统一编辑器宿主：NodeEditorHost.vue 按注册表解析 nodeDef.editor 渲染，通过 ruleDesignerStore.openEditor(nodeId, listKey, itemIndex) 打开，saveEditor 将补丁 merge 回节点数据。
  • Store 共享数据：ruleDesignerStore.ts 持有 ruleData/variables/editor 状态，通过 setCanvasApi({ getNode, getNodeData, updateNodeData }) 注入画布访问器，避免组件间直接耦合。
  • 动态画布插槽：RuleDesigner 用 v-for="def in registeredDefs" #[\node-${def.type}`]动态渲染专用节点插槽 +#node-generic` 兜底，新增节点自动获得画布渲染。

使用示例

// 在 FormPage.vue 中

  formId: computed(() => props.compList?.[0]?.formId ?? ""),
  formFields: tableFieldList,
  formData: computed(() => formPageRef.value?.getFormData()?.value ?? {}),
  enabled: computed(() => !!ruleFormId.value),
});

// ON_LOAD: 在 StarHorseForm 的 @dataLoaded 事件中调用
const onFormLoad = async () => {
  await triggerOnLoad();
};

// ON_CHANGE: 由调用方 watch formData（300ms 防抖）后调用
watch(formData, useDebounceFn(triggerOnChange, 300));

// ON_SUBMIT: 在 merge 前调用
const handleMerge = async (type: string) => {
  const ok = await triggerOnSubmit();
  if (!ok) return;
  formPageRef.value?.merge(type);
};

设计原则

  1. 融入已有事件流，不新增并行事件系统
  2. ON_LOAD → 复用 @dataLoaded
  3. ON_CHANGE → 表单级 watch formData（debounced），规则引擎是表单级服务
  4. ON_SUBMIT → 复用 merge/validate
  5. applyActionsToFormFields → 与 shplugin controlFieldProps 保持一致

与 dataRelation 的关系

  • dataRelation：字段级轻量联动，同步执行
  • 规则引擎：表单级，异步执行（300ms 防抖）
  • 执行时序：字段变更 → dataRelation 同步 → 300ms 后规则引擎异步 → 覆盖前者（业务规则优先级更高）

extractFieldMetaList

  2. 补充路径：直接遍历原始 compList，捕获 analysisCompDatas 可能遗漏的字段

支持所有容器结构：box（二维数组扁平化）、dytable、table、tab、card、collapse、splitter、condition、step，以及 children/items 嵌套。

box-container（栅格盒子）

最常用的布局容器，支持行列栅格布局。

  • 配置结构：preps.elements[]，每个 element 含 columns[]，每个 column 含 items[]（字段数组）
  • 行数/列数：通过 rowNums / columnNums 描述（由 boxUtils.ts 从 elements 网格结构推导）
  • 渲染：经 analysisCompDatas 解析后，box 的 fieldList 会扁平化为二维数组（多个字段可共享同一单元格列）

dytable-container（动态表格）

支持动态行增删的表格容器，适用于明细表、子表单场景。

  • 配置结构：preps.elements[] + preps.dytableList（二维数组）
  • 列项：dytable-col.vue
  • 能力：行增删、列配置、单元格字段编辑

table-container / gridtable-container

  • table-container：普通表格容器，preps.containerType === "table"，preps.containerFields[] 含 fieldList
  • gridtable-container：网格表格容器，纯展示型，列项为 gridtable-col.vue

这四种容器结构相似，均通过 preps.elements[] 组织，每个 element 含 items[]（字段数组）：

  • tab-container：标签页，preps.tabList[]
  • card-container：卡片分区，preps.cardList[]
  • collapse-container：折叠面板
  • splitter-container：分割面板（水平/垂直分割）

step-container（步骤条）

向导式表单容器，按步骤分页填写，适用于多步表单流程。

anchor-container（锚点）

锚点导航容器，长表单场景下提供锚点快速定位。

condition-container（条件容器）

按条件渲染不同子项的容器：

  • 配置结构：preps.children[] 或 preps.items[]
  • 渲染：condition-node.vue 作为条件节点项
  • 经 analysisCompDatas 解析后：产出 { fieldName, children, compType: "container", itemType: "condition" }

dialog-container / drawer-container

弹窗/抽屉容器，内嵌表单：

  • dialog-container：对话框内嵌表单
  • drawer-container：抽屉侧滑内嵌表单

fieldset-container / group-container / descriptions-container

  • fieldset-container：字段集，带标题的分组容器
  • group-container：通用分组容器
  • descriptions-container：描述列表，只读详情展示（Element Plus Descriptions 风格）

// 规则引擎自动配置

const ruleFormData = computed(() => formRef.value?.getFormData()?.value ?? {});

configureRuleEngine — 规则引擎 API 端点

定义于 src/api/rule_engine_api.ts：

interface RuleEngineApiConfig {
  serviceName: string;            // apiInstance 服务名，默认 "userdb-manage"
  ruleDefinitionPath: string;     // 规则定义路径，默认 "userdb/ruleDefinition"
  ruleConditionPath: string;      // 规则条件路径，默认 "userdb/ruleCondition"
  ruleActionPath: string;         // 规则动作路径，默认 "userdb/ruleAction"
  ruleSetPath: string;            // 规则集路径，默认 "userdb/ruleSet"
  ruleSetItemPath: string;        // 关联项路径，默认 "userdb/ruleSetItem"
  ruleVariablePath: string;       // 变量路径，默认 "userdb/ruleVariable"
  ruleExecutionLogPath: string;   // 执行日志路径，默认 "userdb/ruleExecutionLog"
  ruleEnginePath: string;         // 引擎执行路径，默认 "userdb/ruleEngine"
  ruleVersionPath: string;        // 版本路径，默认 "userdb/ruleVersion"
}

configureRuleEngine(cfg: Partial<RuleEngineApiConfig>): void
getRuleEngineConfig(): Readonly<RuleEngineApiConfig>

最终请求路径为 /{serviceName}/{xxxPath}/具体操作。例如默认配置下执行接口为 POST /userdb-manage/userdb/ruleEngine/executeByForm/{formId}?triggerEvent=ON_LOAD。

// 完全自定义
configureRuleEngine({ serviceName: "my-service", ruleEnginePath: "api/v2/ruleEngine" });
// 仅改服务名，其余路径沿用默认
configureRuleEngine({ serviceName: "custom-gateway" });

FormController.java

表单实时协作控制器，基于 STOMP 消息映射。使用 ConcurrentHashMap + ReentrantReadWriteLock 保证多用户并发安全。

消息端点

端点 方法 说明
/app/form/lock-component lockComponent 锁定组件
/app/form/unlock-component unlockComponent 解锁组件
/app/form/sync-data syncData 同步表单数据
/app/form/register-form registerForm 注册表单信息

广播通道

所有消息广播到 /form/{formId}/message。

1. lock-component（锁定组件）

请求 payload：

{
  "compId": "组件ID",
  "formId": "表单ID",
  "userInfo": { "name": "用户名", ... }
}

处理逻辑：

  1. 获取写锁
  2. 检查组件是否已被锁定（componentLocks 中是否存在 compId）
  3. 未锁定 → 锁定成功，记录 LockInfo(userInfo, timestamp)
  4. 已锁定 → 返回失败消息

广播响应：

{
  "type": "lock",
  "compId": "组件ID",
  "success": true/false,
  "message": "...",
  "userInfo": { ... }
}

锁定成功时额外广播 lock-status 消息：

{
  "type": "lock-status",
  "compId": "组件ID",
  "userInfo": { ... }
}

2. unlock-component（解锁组件）

请求 payload：

{
  "compId": "组件ID",
  "formId": "表单ID"
}

处理逻辑：获取写锁，从 componentLocks 移除 compId，广播 unlock + lock-status（userInfo 为 null）。

3. sync-data（同步表单数据）

请求 payload：

{
  "formId": "表单ID",
  "data": { ... }
}

处理逻辑：广播 sync 消息到所有用户：

{
  "type": "sync",
  "data": { ... }
}

4. register-form（注册表单信息）

请求 payload：

{
  "formId": "表单ID",
  "formInfo": { ... },
  "formData": { ... },
  "list": [ ... ]
}

处理逻辑：保存表单信息（示例中仅打印日志），广播注册成功响应。

并发安全

  • componentLocks：ConcurrentHashMap<String, LockInfo>，存储组件锁定状态
  • lock：ReentrantReadWriteLock，读写锁保证锁定/解锁操作的原子性
  • LockInfo：内部静态类，含 userInfo 与 timestamp

与前端的对接

前端实时协作服务位于 src/components/system/items/FormSocketService.ts，基于 stompjs + sockjs-client 实现：

  • 连接 WebSocket 端点
  • 发送锁定/解锁/同步消息
  • 订阅 /form/{formId}/message 接收广播
  • 组件锁定状态同步到设计器画布

在线协作功能目前标记为不成熟（FormConfig.cooperationMode），此前端为示例实现。
